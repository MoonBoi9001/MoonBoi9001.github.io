01

Selected work

The indexing payments stack on The Graph, end to end. All code is public.

subgraph-dips-indexer-selection

Python
Flagship · who gets paid

Picks which indexers are offered agreements. Prototyped the scoring model in a notebook, then rebuilt it as an always-on HTTP API on Kubernetes with a daily pipeline replaying about 1.7 billion gateway query records from Redpanda. Designed the statistical model at its core: a linear regression estimating each indexer's true latency while controlling for the distance a query travels, with per-indexer confidence intervals, fitted on balanced samples so busy indexers don't drown out quiet ones. Selection then blends economic security, price, latency, uptime and success rate, preferring indexers already synced so data is queryable sooner.

dipper

Rust
Paying side

The service that offers indexing agreements to indexers and manages each offer from proposal through settlement and withdrawal. Effectively its only engineer from December 2025 to August 2026, writing 113 of the 119 changes merged in that window (the rest were automated dependency updates). Designed the agreement lifecycle state machine, the chain listener, and the recovery paths that keep a dataset served when an indexer rejects, never answers, or quietly stops indexing. Moved payments from off-chain signed vouchers to on-chain escrow, coordinated across 4 repositories.

rewards-eligibility-oracle

Python
Who earns rewards

Decides which indexers qualify for The Graph's indexing rewards and records the decision on-chain on Arbitrum. Built the service and the criteria it enforces: a rolling 28-day window counting days an indexer served queries meeting published thresholds for response status, latency and freshness. Took it to production with RPC failover, gas bounds, a circuit breaker, and Slack and Opsgenie alerting.

indexer-rs

Rust
Receiving side

The service indexers run to receive, verify and answer agreement proposals over gRPC. Wrote 25 of the 26 changes merged to its DIPs code between January and August 2026. Rebuilt the trust model: proposals are now attributed to whoever actually signed them and accepted only if that signer is on the protocol's on-chain list of approved payers, rather than trusting a sender field anyone could fill in.

indexer

TypeScript
Accepting side

Moved on-chain acceptance onto its own parallel loop so agreements stopped expiring unaccepted under a backlog, then fixed 3 ways the agent quietly cost indexers money: dropped final payments, allocations left indexing unpaid, and live agreements destroyed by closing a stale allocation.

indexing-payments-subgraph

AssemblyScript
Shared record

Created the shared view of the on-chain record both sides read: indexes agreement and offer events from The Graph's contracts and serves them from a single GraphQL endpoint, so the paying service can reconcile and backfill without calling contracts over RPC on every catch-up pass.
